# 客户端接入契约（手机号验证码登录 · 下期 / 同事对接）

本期只交付**服务端 + 后台**（`license_server/`）。客户端阅读器（reader / proofread 侧）
接入手机号验证码登录时，照本契约实现即可——服务端返回结构与现有 `/account/login` **完全一致**，
`auth-guard.js` 与 `/api/me` 无需改动。

## 一、服务端已提供的两个新端点（无需再改服务端）

### 1. 发送验证码
```
POST {SERVER}/account/sms/send
Content-Type: application/json
body: { "phone": "13800138000", "scene": "login" }   // scene 可省
```
- 成功：`{ "ok": true, "ttl": 300, "cooldown": 60 }`
- 失败：`{ "ok": false, "reason": "cooldown|daily_limit|bad_phone|sms_failed", "retry_after": <秒> }`
  （`cooldown`/`daily_limit` 返回 HTTP 429，其余 400/502）

### 2. 验证码登录（新手机号自动建号 + 开 7 天试用）
```
POST {SERVER}/account/login/phone
Content-Type: application/json
body: { "phone": "...", "code": "123456", "fingerprint": "<机器指纹>", "app_version": "1.0.x" }
```
- 成功：`{ "ok": true, "cred": "<服务器Ed25519签名的account令牌>", "account": {status,tier,expires_at,...} }`
  —— 结构与现有 `/account/login` 相同，直接复用现有落盘/验签逻辑。
- 失败：`{ "ok": false, "reason": "bad_code|code_expired|too_many_attempts|disabled" }`

## 二、reader 端要新增的接入点（single 模式）

对齐现有用户名密码登录的调用链，逐层加一条手机号分支：

1. **`proofread/licensing/client.py`**：加两个方法
   - `sms_send(phone)` → `POST {SERVER}/account/sms/send`
   - `account_login_phone(phone, code, fingerprint, app_version)` → `POST {SERVER}/account/login/phone`
   - 复用现有 6s 超时 + 失败软返回 `network` 的封装范式。

2. **`proofread/license_api.py`**：加封装，登录成功后把 `cred`/`session_id`/`account`
   写入 `license.json`（**复用现有 `_save_account_response`**，与用户名登录同一套本地凭据存储）。

3. **`proofread/auth_api.py`（single 分支）**：加两个代理路由
   - `POST /api/sms/send` → `license_api.sms_send(...)`
   - `POST /api/login/phone` → `license_api.account_login_phone(...)`
   - 仿现有 `account_login` 的 single 分支写法。

4. **`static/login.html`**：加「手机号登录」tab
   - 输入手机号 → 「获取验证码」按钮（点击后 `POST /api/sms/send`，成功进入 60 秒倒计时禁用）
   - 验证码输入框 → 「登录」按钮（`POST /api/login/phone`，成功 `location.href = "/"`）
   - 复用现有 `post()` 辅助函数与页面样式（`--accent` 等 CSS 变量、`.tab`/`.btn`/`.msg` 结构）。

## 三、不用改的部分

- `static/auth-guard.js`：401 拦截跳登录、`/api/me` 校验、换号清缓存——逻辑不变。
- `/api/me`、`require_license` 授权门、使用汇总、后台——全部复用，手机号登录只是「多一种进门方式」。
- 手机号账号在服务端**禁用密码登录**（建号时写随机不可用密码），无需客户端处理密码找回。

## 四、交互时序（供前端参考）

```
用户输手机号 ──▶ 点「获取验证码」──▶ POST /api/sms/send ──▶ 60s 倒计时
     │                                                          │
     └────────── 收到短信，填 6 位码 ◀───────────────────────────┘
                          │
                          ▼
                 POST /api/login/phone ──成功──▶ 写 license.json ──▶ 进入主界面
                          │
                          └──失败(bad_code/expired/...)──▶ 就地提示，可重填/重发
```
