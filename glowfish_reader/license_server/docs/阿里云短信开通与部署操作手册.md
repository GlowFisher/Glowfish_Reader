# 阿里云短信开通与部署操作手册（手机号+验证码登录）

本手册对应 `license_server/` 这套服务端登录鉴权 + 后台管理，指导如何把
「手机号 + 短信验证码」登录从零开通并上线到香港阿里云机
（`license.glowfishreader.com` / 47.83.12.17）。

---

## 前置判断：账号是「中国站」还是「国际站」

发给 +86 大陆手机号，**必须用「中国站（国内消息）」短信服务**，最便宜（验证码约
0.045 元/条），代码里的 endpoint（`dysmsapi.aliyuncs.com` / `cn-hangzhou`）就是它。

- 香港机用 **aliyun.com（中国站）账号** → 同账号开通国内短信，最省事。
- 香港机挂在 **alibabacloud.com（国际站）账号** → 国际站短信是另一套产品，发大陆号又贵。
  建议用一个中国站账号专门开国内短信。**香港机调哪个账号的短信只看填的 AccessKey 属谁，
  和 ECS 在不在同一账号无关**——可以「香港机在国际站、短信 AK 用中国站账号」。

> 💡 **最省事的联调技巧**：阿里云短信控制台有「测试服务」专区，提供免审核的
> 测试签名 + 测试模板，绑定自己的手机号后立刻能发真短信，不用等审核（约 1 工作日）。
> 建议先用它把 `SMS_PROVIDER=aliyun` 全链路跑通，审核通过后再换正式签名/模板。

## A. 阿里云侧开通（一次性，主要在等审核）

### A1. 开通短信服务 + 充值
1. 中国站控制台搜「短信服务」进入（`dysms.console.aliyun.com`），首次点「开通」（按量付费）。
2. 账户余额 ≥ 20 元即可起步（够上千条验证码）。

### A2. 申请短信签名（⚠ 个人主体的坑）
路径：短信服务 → 国内消息 → 签名管理 → 添加签名
- 签名内容：2–12 字，如 `小青鱼阅读器`（显示成 `【小青鱼阅读器】您的验证码…`）。
- 适用场景：验证码。
- 签名来源：个人认证账号只能选「APP 应用名称 / 网站名称 / 公众号或小程序名称」，
  且需提供佐证。桌面软件最稳的佐证是**软件著作权证书**；或用**已备案的官网 + ICP 备案号**
  （官网 `glowfishreader.com` 若已备案可用）。
- 审核约几小时~1 个工作日。个人签名审核卡壳时，先用测试签名联调，正式签名慢慢补。

### A3. 申请短信模板
路径：国内消息 → 模板管理 → 添加模板
- 模板类型：验证码
- 模板内容：`您的验证码为 ${code}，5 分钟内有效，请勿泄露。`
  （变量名必须是 `code`，与代码里 `TemplateParam={"code": code}` 对应）
- 审核通过后拿到模板 CODE，形如 `SMS_123456789`。

### A4. 创建 RAM 子账号 + AccessKey（别用主账号 AK）
路径：控制台搜「访问控制 RAM」→ 身份管理 → 用户 → 创建用户
1. 勾选「OpenAPI 调用访问」（才生成 AccessKey）。
2. 创建后**立即保存** AccessKey ID / Secret（Secret 只显示一次）。
3. 加权限：用户详情 → 添加权限 → 搜 `AliyunDysmsFullAccess` 勾上（最小权限）。

到此手里应有 4 样：`AccessKey ID`、`AccessKey Secret`、`签名名称`、`模板 CODE`。

## B. 香港机侧部署（推新代码 + 配置）

⚠ **关键**：香港机现在跑的可能是旧版服务端（没有 `sms.py` 和两个新端点）。
光填 env 没用，**必须先把更新后的服务端代码部署上去**。

### B1. 推送新代码
用部署脚本（把整个目录 scp + cp -r 上去，新文件 `sms.py`、`tests/` 会自动带上）：
```bash
# 在 server/deploy/ 下
bash deploy_hk.sh
```
> deploy_hk.sh 已配 `SshTarget=root@47.83.12.17`、SSH 私钥。只想手动推改动文件也可以：
> ```bash
> scp core.py sms.py serverapp.py root@47.83.12.17:/opt/shupai/license_server/
> ```

### B2. 填配置（SSH 到香港机改 env）
```bash
ssh root@47.83.12.17
nano /etc/shupai/license.env
```
加入/改好（其余 SERVER_PRIV 等原样保留）：
```ini
SMS_PROVIDER=aliyun
ALIYUN_AK_ID=你的AccessKeyID
ALIYUN_AK_SECRET=你的AccessKeySecret
ALIYUN_SMS_SIGN=小青鱼阅读器
ALIYUN_SMS_TEMPLATE=SMS_123456789
SMS_SEND_COOLDOWN=60
SMS_DAILY_LIMIT=5
SMS_CODE_TTL=300
```
确认权限（含密钥，必须 600）：
```bash
chmod 600 /etc/shupai/license.env && chown shupai:shupai /etc/shupai/license.env
```

### B3. 重启服务（EnvironmentFile 自动加载新变量，systemd 单元不用改）
```bash
systemctl restart shupai-license
systemctl status shupai-license --no-pager      # 看 active (running)
```

## C. 联调验证（上线前必做）

在香港机本地直接打接口（服务监听 `127.0.0.1:8800`），用自己的手机号：
```bash
# 1) 发验证码
curl -s -XPOST http://127.0.0.1:8800/account/sms/send \
  -H 'Content-Type: application/json' -d '{"phone":"你的手机号"}'
# 期望 {"ok":true,"ttl":300,"cooldown":60}，手机应收到短信

# 2) 用收到的验证码登录（新号自动建号 + 开 7 天试用）
curl -s -XPOST http://127.0.0.1:8800/account/login/phone \
  -H 'Content-Type: application/json' \
  -d '{"phone":"你的手机号","code":"收到的6位码","fingerprint":"test","app_version":"test"}'
# 期望 {"ok":true,"cred":"...","account":{"status":"trial",...}}
```

**排错**：第 1 步返回 `{"ok":false,"reason":"sms_failed"}` 时，去阿里云短信控制台
「发送记录/统计」看拒发原因，常见：签名/模板未审核通过、余额不足、该号触发阿里云自身频控。
看服务端日志（阿里云错误码已打进日志，手机号脱敏）：
```bash
journalctl -u shupai-license -n 50 --no-pager
```

**后台核对**：浏览器开 `https://license.glowfishreader.com/admin` 登录，
列表应能看到该手机号账号、状态 `trial`，也能按手机号搜索。

## D. 防刷阈值说明（真金白银）

- 同号发码冷却 `SMS_SEND_COOLDOWN=60` 秒；同号单日上限 `SMS_DAILY_LIMIT=5` 条。
- 验证码 6 位、`SMS_CODE_TTL=300` 秒过期、最多 5 次校验、单次有效、哈希存储。
- ⚠ 设计要点：验证码校验成功时只清空验证码、**不删发送节流账本行**——否则登录一次就
  重置冷却与单日上限，短信费防刷失效。
- 可选加固（未做）：发码前加图形验证码/滑块挡机器刷。

## 本地开发自测（无需短信、无需上线）

服务端登录鉴权本地即可自测，`SMS_PROVIDER=console` 时验证码只打日志不真发：
```bash
# 在 server/ 目录，需含 fastapi + pynacl 的 python 环境
python tests/test_phone_login.py
# 覆盖：发码→验证码登录→7天试用→cred验签→单次有效→复登不重复送试用→
#       防刷(冷却/日限/连错锁定/过期)，14 断言应全绿
```
