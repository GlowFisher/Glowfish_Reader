## 迭代 1 · 夹注读序——双行小字检测与层级读序（纯几何，零模型）

**动因**：s02 的 5% 失分几乎全是夹注读序。`aggregate_columns`（proof_model.py:91，x-overlap≥0.5 并查集）会把夹注左右小行误并（y 重叠 → 文字交错）或误拆（`default_order` 按 -mean_x 把左小行排到下一列后）；无层级读序概念。

**设计**：新增 `proofread/interlinear.py`，挂 `build_proof` 内 `aggregate_columns` **之前**（不动 aggregate_columns/default_order——有单测锁定行为，且正是病灶所在）。把配成对的夹注合并为**合成行**（text=右行+左行、box=并集、score=min、`interlinear:true`、保留 member_boxes/member_texts/🆕member_scores）——合成行宽≈主列宽，下游并查集/排序零改动自然工作。🆕 注意 score=min 会让合成行更易触发迭代 3 的纠错（score<0.85），属期望行为；审计与 UI 定位需能靠 member_* 还原到成员小行。

**算法**（行框几何）
1. 主列宽 W = 页内行框宽前 60% 分位的中位数。
2. 候选小行：宽 ∈ [0.3W, 0.65W]。
3. 配对三条件：y 重叠率 ≥0.6；x 互补（并集宽∈[0.8W,1.3W] 且交叠≤0.25×小行宽）；高度比∈[0.5,2]。
4. 配不上对的候选一律不动（**宁漏勿错**）；三行小注/眉批 out of scope。

**任务**
- [ ] 新增 `proofread/interlinear.py`（纯函数：检测+配对+合成）。
- [ ] `proof_model.build_proof` 一行接入，`SHUPAI_INTERLINEAR=0` env/config 开关。
- [ ] 新增 `proofread/test_interlinear.py`：正对/伪对（碎裂半宽噪声行）/单行/全链读序用例。

**验收**：s02 计序 CER 较迭代 0 基线降 ≥50%（夹注段 30 字读序全对即达成）；s01/s03 等无夹注样张 F1/CER 波动 <0.005；`test_proof_model.py` 全绿。

## 迭代 3 · 上下文语义修复层——现成古文 MLM 重打分纠错（本方案核心增量）

**动因**：s03 型形近误认（62 处）是最大失分项；形近字对不携带方向信息（「盗」在别的文档合法），判定"是否误认"只能靠**上下文语义**——用现成古文预训练 MLM 提供整句上下文概率，替代自训模型（别人已花大成本在古文语料上训好，零训练拿来推理）。

### 3a. 模型选型与集成

🆕v1.2 **为什么是 MLM-BERT 这一类（选型论证，硬约束推导）**：App 打包无 torch、推理只有 onnxruntime、int8 后 ~100MB、CPU 页级延迟预算 → 模型类只能是小型编码器。在该类内，MLM 与本任务**零任务错配**——"固定位置、双向上下文、封闭候选集重打分"就是 MLM 的预训练目标本身。已排除的替代类：小型因果 LLM（Qwen 0.5B 级，int8 仍 >400MB 超打包预算，单向上下文对位打分需两遍、CPU 延迟不可接受）；n-gram/统计 LM（窗口小、对形近字无方向判别力，前轮评审已否）；现成 CSC 模型（MacBERT4CSC，现代中文域错配文言，前轮已判只借配方不借权重）；ELECTRA 判别器（RTD 任务与"该字是否被替换"天生同构、理论最优，但无现成古文 checkpoint，自训超预算 → 记入"暂不做"远期）。**结论：现成古文 MLM-BERT 是当前约束下的最优类，选型只在该类内挑 checkpoint。**

- [ ] **选型冒烟**：GuwenBERT（殆知阁古文语料，简体，首选——与 405 万字语料、简体辑录交付同侧）vs SikuBERT/SikuRoBERTa（四库全书，繁体）🆕v1.2 vs GujiBERT/GujiRoBERTa（古籍智能系列，语料更广）。hf-mirror 拉取，🆕v1.2 判别力基准定量化为**同一把尺**（后续 3a′ 微调裁决复用）：①62 处已知错字位（迭代 0 面板落地后扩为面板错位集）上"正字在混淆集内 top-1"命中率；②原字 vs 正字概率差的分离度（AUC）；③退想斋留内 + 公文侧文本伪困惑度。三项取优者胜出。
- [ ] 新增 `proofread/setup_mlm_model.py`：复刻 `setup_punct_model.py` 配方（colorize env + hf-mirror → 导出 ONNX MLM 头 → int8 量化 ~100MB），产物 `proofread/models/mlm/`（gitignore，打包随 spec 带 int8）。App 已带 onnxruntime + int8 标点 BERT（97MB），架构一致。

### 3a′. 域适应微调 A/B（🆕v1.2，1-2 天预算，条件采纳）

**动因**：现成古文模型的预训练语料以先秦—清中期典籍为主，晚清民国文书含大量近代词汇（盐务/票号/机构名/新名词/公文套语），存在域差；用户接受 1-2 天微调预算。1-2 天最划算的花法是 **DAPT（域内继续 MLM 预训练）**——零标注、单卡数小时、产物是同架构 checkpoint，经 `setup_mlm_model.py` 同链路导出，**集成零成本（drop-in 换权重）**。CSC 头微调要造伪错样本、工程链长，仍留"暂不做"。

- [ ] 以 3a 冒烟胜出 checkpoint 为底，在混合语料上继续 MLM 训练若干 epoch：405 万字退想斋 + 公文侧已校订文本（`官网展示\档案\` 录文等），**混域防偏科**（405 万字全是日记体，纯日记 DAPT 可能把公文域越调越偏）。训练脚本落 `D:\CC-train\`（不进 App 仓库），遵长任务铁律 Start-Process 后台跑。
- [ ] ⚠泄漏铁律同 3c：第 117 册（bench s02 段）对应条目 + 全部 gold 录文剔除出训练集。
- [ ] **裁决门（与 3a 冒烟同一把尺，不另立标准）**：held-out 判别力基准上微调版较现成版混淆集 top-1 命中 **+≥5pt**，**且** 3c 空跑误纠率不升（分体裁）→ 换用微调 checkpoint；否则用现成版、微调权重留档。**微调是受控 A/B 不是默认必做**——收益不确定就让同一把尺裁决。
- [ ] 时序：不阻塞 3b/3c 开发（先按现成模型联调全链），微调与之并行，赢了换权重即可。

### 3b. 纠错引擎 `proofread/ocr_correct.py`
挂载：`build_proof` 内 `_proof_line` 产出简体 draft 之后的**简体侧**（语料/模型/交付三者同侧）。

流程：
1. **触发**：行 score < 0.85，或行内字符命中 confusion 表高频对。
2. 对疑错位逐位 mask，**候选严格限定 confusion-set 内**（+原字），MLM 计算各候选概率；上下文窗口取整列文本（列内跨行拼接，竖排语义连续）。
3. **Tier A 自动改**：候选/原字概率比 ≥ T_A（在 405 万字语料上标定），且替换后命中 ≥2 相邻字匹配的词锚。
4. **Tier B 只建议**：概率比中间带 → `suggestions:[{pos,from,to,prob_ratio}]`，保留原文。**单字裸换（已/己类）永只进 Tier B**。
5. 🆕 **两遍收敛（抗邻位错字污染）**：单点 mask 假定上下文干净，但 s03 这类高错密度行常一行多错、互相污染判别力。做法：行内触发位按概率比降序**贪心应用 Tier A**（一遍），用改后文本**整列重打分第二遍**再定剩余位；固定两遍防振荡。
6. 🆕 **性能预算**：疑错位攒 batch 一次 forward（勿逐位单推）；每页 mask 调用设上限（超限降级为只处理 confusion 命中位）；纠错层页级延迟目标 ≤2s（int8 CPU 口径），超限自动收紧触发并记审计——草书页 score<0.85 可能命中大半行，无上限会把点校等待拖爆。
7. **审计**：Tier A 改动记 `corrections:[{pos,from,to,rule}]`；Tier B 采纳/拒绝落档（误纠率持续监控 + 未来训练对采集入口）。

### 3e. 并列人名句读建议（🆕v1.2，Tier B 专属，永不自动改）

**动因**：2c 只能修"已切开但符号错"；「孙文伍廷芳唐绍仪」这类**人名连排、标点模型未切开**的段落是句读难题——切错即改变文义，代价高于错字，故规则不硬切、模型不自改，只出人工确认的建议。

**设计（三信号合议，复用 3b 模型零新增）**：
1. **语境触发**：名单引导词（派/委/举/选/绅商/委员/董事/发起人…）或煞尾词（等/诸人/各员）或落款/名单版式行；无名单语境的段落一律不碰。
2. **姓氏锚点切分**：闭集姓氏表（单姓+复姓，`assets/lexicon/surnames.txt`）锚定候选边界，按"每段以姓氏开头、长 2~4 字"动态规划枚举合法切分；人名词表命中（405 万字语料挖掘 + glowfish 档案元数据人物字段 + 可选 CBDB 开放人名数据离线表）的切分加权。
3. **MLM 裁决**：候选切分间以伪困惑度比较（复用 3b 已加载模型），胜出切分优势超阈值才出建议；姓氏字兼常用字（王/于/白…）导致的歧义正是靠这一步消解。

**验收**：s02 并列段 + 面板名单类样张能出正确建议且人工采纳率 ≥50%；对无名单语境的干净文本空跑**零触发**。
**回滚**：独立 flag；只产建议不改文本，天然无回归面。

**验收**
- 事前闸：空跑审计误纠 <1/10 万字（目标 0，🆕 分体裁各自达标）。
- s03 F1 提升（预期值由错误面板校准，不预设）；s01/s02 及面板样张零回归。
- 🆕 bench 增报「Tier B 全采纳」模拟 F1（天花板值）：Tier A 门槛保守时自动指标可能几乎不动，收益都沉在建议层——没有这个天花板值，容易把"方案有效但闸门紧"误判成"方案无效"。天花板与实际 F1 的差值同时指导 T_A 松紧调参。
- Tier B 建议人工核对采纳率 ≥50% 才默认展示，否则收紧触发。
- 新增 `proofread/test_ocr_correct.py`：每条 confusion/词锚/阈值逻辑一正一反用例。

**回滚**：ocr_correct 总开关 + Tier A/B 独立开关；模型文件缺失时静默降级为纯规则模式（不阻塞主流程）。
**风险**：GuwenBERT 对晚清文书域仍有偏 → 选型冒烟先行 + 域内阈值标定兜底；改掉正确生僻原文 → 候选限表 + 词锚 + 空跑审计 + 保真字清单（馀/搆等 gold 有意保留字）排除。
